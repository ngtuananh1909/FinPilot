## Approved policies (G1, 2026-11-23)
- **Quota:** 20 chats and 5 receipt scans per user per Asia/Ho_Chi_Minh day, for guests AND each of the 3 email demo accounts, independent per user.
- **Quota reservation:** reserve atomically before the provider call. Release (idempotent, keyed by request id) when the request clearly fails before a usable result (invalid configuration, definitive provider rejection). For ambiguous timeouts keep at most one reservation. No automatic retries beyond a strict limit.
- **AI transport:** one OpenAI-compatible transport for Gemini and OpenRouter, no vendor SDKs without approval, max 4 tool steps, timeout, Zod-validated tool args. Capability probes run only as an explicit manual script, never per user request. No mocked AI success.
- **Amplify:** Next.js 15.x only; no streaming, Edge API routes or `unstable_after`. Document the server env-variable procedure for G4; never log or commit secret values.

- **Reset (owner decision):** manual reset is allowed for guests AND for the 3 email demo accounts, only by the signed-in owner after explicit confirmation; the route handler derives the user id from the verified session. Reset never touches `ai_usage_daily`.
- **Guest quota bypass via new anonymous identities:** deferred by owner (no IP limiting for now); revisit before public launch.
- **AI billing (owner decision 2026-11-24):** no paid tier; when a Gemini free-tier key is exhausted the owner supplies a key from another project/account. Each key change on Amplify needs an env update + redeploy. Agent noted a possible provider terms-of-service risk; owner accepted.
